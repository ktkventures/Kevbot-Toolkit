# Iteration 0609a — 2m cross-TF gate fails open via frozen confluence records

**Date:** 2026-06-09
**Hypothesis:** Phase 3 / H1 (gate-mode break) — refined. The 06-08 memo blamed
"2m cross-TF live records missing since ~06-03." That premise is **wrong** as of
today's data: the 2m secondary builder is alive (291 live_bars today). The real
mechanism is **stale/frozen** records, not missing ones.
**Test bucket:** C (local replay harness) — Bucket B (deploy + live measure) pending Kevin approval
**Branch:** feat/claude-iter-0609a (backup: claude-iter-pre-2026-06-09-backup)

## Root cause

Live path: worker runs `RalphEngine`; gate is `unified_engine.PositionStateMachine.check_entry`
(imported into ralph) — one implementation, shared with backtest.

In `SymbolHub._fanout_to_secondary_builders` (`ralph_engine.py:2699`), the
`sec_was_duplicate` (rebroadcast) branch called `shadow.indicators.recompute_from_history()`
but **`continue`d without writing `_mtf_confluence[sec_tf]`** ("don't re-emit confluence
records"). So whenever a secondary close is flagged a duplicate, the cross-TF gate record
**freezes at the state it held on the first real close after worker start.**

- SPY 2m closes are flagged duplicate essentially every bucket (logs show a constant
  `Rebroadcast cascade: shadow SPY/120s recomputed`), so `_mtf_confluence[120]` never moves.
- sid 277 gate = `2m-BOLLINGER_BANDS-SQUEEZE_UPPER`. If frozen on `SQUEEZE_UPPER` → gate
  passes every bar → flood. This also explains the "gating works off and on" symptom:
  it's deterministically stuck at whatever the 2m indicator was doing at worker boot.

The 06-08 proposed "fail-closed guard" would NOT fix this — records aren't empty (10Sec
primaries always carry their own `10S-*` records), they're present-but-stale.

## Pre-change baseline (flood signature, today 2026-06-09 RTH, user 19d47e46)

- Alerts today by ~13:55 ET: 275 / 345 / 361 / 310

  SQUEEZE_MID 48.1% / SQUEEZE_LOWER 30.8% / **SQUEEZE_UPPER 21.1%**
  → a *fresh* gate passes 21% of bars; frozen-on-squeeze passes 100%. **That gap is the flood.**

## Change

- Files modified: `src/ralph_engine.py` (+45/-6)
- Added `_ShadowIndicatorEngine.recompute_confluence(history_df)` — recomputes indicators
  from corrected history AND re-derives confluence records (mirrors `on_bar_close`, using
  `get_values()`/`get_prev_values()` after the O(1) correction).
- Rebroadcast branch now does `_mtf_confluence[sec_tf] = shadow.recompute_confluence(...)`
  instead of recompute-only. Shadow records drive only gating (no triggers/positions/alerts),
  so re-emitting is safe; the "don't re-emit" rule was inherited from the primary own_records
  path where re-emit could double-fire alerts.
