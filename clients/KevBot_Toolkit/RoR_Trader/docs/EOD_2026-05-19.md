# EOD 2026-05-19 — Worker lag-spiral incident: diagnosed & fixed end-to-end

A full-day incident + fix. The Railway Worker's A-channel ingestion lag
ran away during RTH (12s → 75s → 250s+, climbing); by EOD it is **stable
at ~3.7s avg** — at the achievable floor.

## Timeline

| A-lag avg | Stage |
|---|---|
| 250s+ ↗ | RTH spiral (incident) |
| 7.5s | after spiral fix |
| **3.7s** | after O(1) recompute fix (min 3.06s, max 6.3s, 100% <10s) |

## Root causes & fixes (9 commits on `dev`)

1. **`vwap_v2` exception storm** (`beeaca7`, `f09d8a8`) — the pack called
   `.timestamp()` on a live bar's `timestamp`, which is an **ISO string**
   live (a pandas Timestamp in batch/warmup). Threw every bar. Fixed via
   `isinstance` coercion. (First attempt used `hasattr` — banned by the
   pack sandbox; hence fix #2.)
2. **Pack-params DB storm** (`87e692d`) — `recompute_from_history` re-ran
   `IncrementalIndicatorEngine.__init__` per WS rebroadcast, each doing a
   blocking (failing, `user_id=eq.None` 400) `load_confluence_groups` DB
   call. Now caches resolved pack params per engine.
3. **The spiral** (`a63320e`, `fe003b9`) — under backlog, every late /
   re-delivered per-second bar for a closed bucket triggered a full
   `recompute_from_history` sweep across all 11 SPY 10Sec monitors.
   Slow sweep → more backlog → more re-deliveries → more sweeps.
   Fixed with `BarBuilder.last_was_correction` + a monotonic
   `_last_rebroadcast_recompute_ts` — one recompute per bucket, max.
4. **`recompute_from_history` itself** (`2785d2d`) — profiling proved it
   was 90-95% of worker CPU: ~710ms/call, an O(N) replay of the entire
   intraday history on every Polygon correction. Replaced with **O(1)
   snapshot/restore**: `update_bar` snapshots pre-bar engine state;
   `apply_last_bar_correction` rewinds one bar and re-applies the
   corrected bar. recompute: **710ms → 0.5ms**. Verified bit-identical.
5. **Pack validation hardening** (`40cf82e`) — `validate_builtin_usage`
   AST allowlist check rejects packs using non-sandbox builtins at
   install; pack-creation AI context documents the sandbox + the
   `timestamp`-type gotcha.

Profiler: `790a8f6`, `397834e` — `HOT_PATH_PROFILE` env-flagged hot-path
timing (left in, ~zero overhead off).

## State of things

- **Worker healthy** — A-lag ~3.7s avg, ~25% CPU. The residual ~0.7s
  (avg vs the 3.06s min) is Polygon RTH A-channel delivery jitter, not
  worker lag — the worker now adds ≈0.
- **The 2.5-3s target** — 2.5s is below Polygon's structural minimum
  (observed min 3.06s, steady all day). 3s is a best-case; 3.7s is the
  realistic RTH average. The after-hours "~3s" was a thin-sample best
  case. Beating 3.7s needs a faster data source, not worker code.
- **Grace shadow** still OFF (`GRACE_SHADOW_ENABLED=false`). A **Grace 5s**
  variant was added (`_DEFAULT_GRACE` now `2,2.5,3,4,5`; API allowlist +
  Bars Comparison UI) — when the shadow is re-enabled, size the 10Sec
  grace window against the RTH ~3.7s reality (likely Grace 4 or 5).
