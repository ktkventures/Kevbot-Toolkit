## Scope split — M-RS5 is TWO deliverables

### M-RS5b — canonical fine-TF gate state on the LIVE Worker (fidelity/architecture; SMALL)
**Goal:** one construction path for cross-TF gate state. At each fine-TF secondary close,
derive the shadow's published state from the engine's OWN canonical 1Min resample
(the `canonical_upto` pattern — proven in the replay harness; zero DB reads, the engine
already holds its 1Min series) instead of incremental fan-out state + periodic re-true.
- **Why:** retires the two-path band-aid permanently — no between-refresh drift window, no
  cascade/poison/re-true bug class possible, session-open state == canonical by construction.
  Directly targets 328's residual class and the 327 ceiling wobble.
- **Cost note:** `recompute_confluence` per fine-TF close ≈ what the refresher already does
  every 120s, just aligned to closes; bounded by TF cadence (2m/3m/5m). In-memory, no DB.
- **Flag:** `RORT_CANONICAL_FINE_TF_STATE` (default OFF). The refresher stays armed until 5b
  is green, then `RORT_MTF_STATE_REFRESH_S` can be retired (or kept as a cheap backstop).
- **Gates:** (1) replay-harness A/B — today's + prior settled days, canonical-state replay
  vs current-stack replay vs backtest, expect ≥= current ceilings, 328 improved;
  (2) unit: state at every fine close == `recompute_confluence(canonical_upto())`;
  (3) canary arm (TSLA hub) → fleet. Effort: **~1-2 sessions.**

### M-RS5a — resident data window on the SHADOW-WORKER (cost/scale; BIGGER)
The 07-06 design stands (prep-once, feed-deltas; ~100-1000× DB-read collapse; restores 5s
poll cadence; POLL_S=60 retires). **Design updates from what we've learned:**
- **Bootstrap from the resampled store** (M-RS2 P2) where a slot's TF/session is covered —
  the store IS the resident frame's settled prefix; only head/edge needs live prep.
- **REVISION RE-FEED is mandatory** (07-06 risk #3 was right): sweeper corrections to
  consumed bars → re-apply from that bar forward or drop-frame → cold re-prep.
- **Comparator = the replay-harness pattern** (dashboard-scored byte-diff), not a bespoke
  harness — most of gate #2's tooling now exists.
- Promotion gates + kill switches unchanged from the design doc. Effort: **2-4 sessions.**
